## Project information model

Each project should be understood through these dimensions:

```text
WORLD
 ├── PURPOSE
 ├── REPOSITORY
 ├── ARTIFACTS
 ├── TECHNOLOGIES
 ├── CAPABILITIES
 ├── TIMELINE
 └── RELATIONSHIPS
```

## Evidence hierarchy

1. Repository source and documentation
2. World Model entities and relationships
3. Explicit project documentation
4. Narrative interpretation
5. Future roadmap

The lower levels must never contradict stronger evidence.

## Status vocabulary

- **Implemented** — exists in the current codebase
- **Prototype** — functional experimental implementation
- **Planned** — intended but not implemented
- **Experimental** — exploratory technical direction
- **Pending repository** — project exists in the portfolio model but its canonical source repository has not yet been connected

## Why this structure exists

Phase III-E makes the project directory part of the same semantic architecture as the planetary UI, repository ingestion and AI Navigator. Project documents are therefore written as dossiers that can later become World Model documents and embedding chunks.

## Next evolution

As live GitHub ingestion matures, repository metadata, source documents, discovered artifacts and technology versions will supersede manually maintained implementation details wherever canonical evidence is available.
