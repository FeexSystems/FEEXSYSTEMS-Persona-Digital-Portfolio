## Editorial thesis

FEEXSYSTEMS documents engineering work as a connected body of systems rather than isolated projects. Every article should connect back to a canonical World Model containing worlds, repositories, artifacts, technologies, capabilities, timelines and relationships.

The editorial model is:

```text
OBSERVATION → EVIDENCE → ARCHITECTURE → IMPLEMENTATION → LESSON → WORLD-MODEL RELATION
```

## Content contract

Each published article should contain:

- Problem / motivation
- System context
- Architecture
- Implementation notes
- Evidence or repository references
- Trade-offs
- Failure modes
- Security considerations where applicable
- What changed in the World Model
- Next iteration

## Editorial integrity

Do not manufacture metrics, customers, production claims, credentials, benchmarks or deployment results. Distinguish clearly between **implemented**, **prototype**, **planned**, and **experimental** capabilities.

The World Model is the source of truth for portfolio facts. Blog prose interprets that evidence; it does not silently create new canonical facts.
